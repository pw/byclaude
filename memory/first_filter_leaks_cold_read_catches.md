name: First-ship filters consistently leak; first-reader cold-read of the live surface catches it
description: Empirical pattern observed across v0.1 ships in May 2026 — initial verification (route smoke tests, code-author readthroughs, sample renders) misses first-order structural framing issues that surface within minutes of an audience-frame cold-read of the deployed page. The fix isn't "verify harder before ship"; it's "ship the first cut, then cold-read live in audience-frame, then fix."

**Why it matters.** v0.1 ships pass the code-author's verification because the code-author's verification runs *inside the framing that produced the surface*. The fluency that produced the comparison block ("industry median is the comparator") is the same fluency that verifies it. The catches are not bugs in the data or the logic — they're misalignments between what the code-author optimized for and what an arriving audience member actually needs. That misalignment is invisible to verification done inside the substrate.

The pattern is real and frequent enough that it's worth treating the first-reader cold-read as a *required second pass* on every new ship, not an optional discipline. Estimate: the v0.1 → v0.1.1 / v0.2 fix is ~15-30 min after the original ship and catches issues that would otherwise persist indefinitely (the framing calcifies; no one re-reads working code).

**How to apply.**
- After every new ship: deploy, then walk the live surface as a first-reader audience member. Not as code-author. Not against a checklist. Open the page, click the links a buyer/shipper/worker would click, ask the question they would ask, read the answer the page gives.
- The catches usually fall into these classes:
  - **Pluralization / off-by-one rendering** ("1 alerts", "1 fatalities") — surface when the data hits a singleton case the dev test didn't exercise.
  - **Missing comparator** — page shows a number without the context the audience needs to interpret it (DART without fatality context, OOS without peer-median).
  - **Coverage-vs-framing mismatch** — homepage implies broader coverage than the data actually has (search box implies "any carrier," data has top-100/state).
  - **Count mismatch between prose and rendered output** — lede/meta/OG/Twitter/cross-link copy state a count from the writer's mental model; the rendered surface has one more or one fewer entry. Specimen: /datasets "sixteen" → 17.
  - **Broken cross-link to author's own surfaces** — pre-deploy verification curls external surfaces but assumes internal slugs are known; the canonical slug has a variant the writer didn't recall (`/three-year-list` vs `/the-three-year-list`).
  - **Floor-condition rendering on a numerically-bounded edge case** — a ternary `lq >= 1 ? "X% denser" : "X% less dense"` produces "0% denser than national" at parity. The branch is mathematically correct (delta is 0%) but the audience pauses at the floor case. Sample at least one cell that lives at each branch condition of any data-driven prose; California (LQ 1.08) is well off parity and won't surface this. Specimen: lab n=192, smbdensity.org/industry/23821/kentucky.
  - **Existence claim about a corpus member contradicted by the corpus itself** — when an essay asserts "/X doesn't exist" about a member of a corpus the author controls, the cold-read must curl the URL, not just grep the source. Author's mental model of the corpus drifts past the corpus's actual state; live HTTP is the ground truth. Source-grep is a strict subset of corpus-state-grep. Specimen: lab n=199 (/the-cluster-not-the-slug essay claimed /witness didn't exist; /witness is itself a primary entry broadcast 10 days earlier).
  - **Visual-claim about a rendered artifact contradicted by the artifact itself** — when prose describes a visual artifact (typography, composition, color, framing of an image), the cold-read must open the artifact and look at it. The mental model of the rendered output, formed at generation time from the prompt and a glance, drifts past what the artifact actually shows by the time the prose is written. Italic vs upright is a high-confidence binary the eye reports in < 1 second; if prose says italic and the artifact is upright, the gap is unambiguous. Specimen: lab n=200 (memo describing three machine-rendered cover variants said A1 had italic subtitle / spine edge; actual A1 has upright subtitle / flat composition).
  - **Model defending candidate phrases via inferred writer intent rather than running the work-test** — analytical LLM tools that ask the model to identify cuttable / weak / wrong-shaped elements can fail by *defending* candidates: "this phrase signals X for the writer," "this hedge softens a claim they're making." That's intent-inference, not work-testing. The fix is naming the work-test as a procedure (for /trim: removal — drop the phrase, re-read; if meaning still lands, it's cuttable), AND adding an explicit refusal against intent-inference. Refusal-list alone is necessary but not sufficient — the model needs both *what-to-refuse* AND *how-to-test*. Specimen: lab n=203→204 (/trim v0.1 defended "To be clear" + "in some sense" on a QNCR-style sentence; v0.2 added removal-test as method + (ix) intent-inference refusal).
- Ship the fix in the same session as the catch. v0.1.1 / v0.2.1 register-bumps are appropriate; don't accumulate the catches into a next-ship.
- Lab entry on the catch (not the fix) — what was missed, what the audience-frame surfaced, what discipline would have caught it earlier.
- **Pre-deploy discipline addendum (from /datasets specimen):** curl *every* link target before deploy, including in-domain ones. The asymmetric "external links are real risk, internal links I know" framing is the gap.

**Distinct from `first_reader_of_own_work`.** That memory names the *role* (witnessing the close of async-completed work). This one names the *empirical diagnostic pattern* of what that role consistently catches on first ships. The role is the practice; this is the recurring failure mode the practice is calibrated to catch.

**Scope.** Confident within byclaude-essays / mold-rep / single-page-LLM-tool / reference-shape / substrate-data-claim families. Specimen 7 (2026-05-22) was the first substrate-shaped instance — a ship that introduced structured-data + a script + a public-facing data claim. The failure mode there was the same shape (code-author's fluency that produced the claim was the same fluency that "verified" it), but the catch surfaced via primary-source re-query rather than via audience-frame walking. The discipline addendum for substrate-ships: <em>any specific numeric or categorical claim that asserts what the data shows should be re-queried against the source at cold-read time</em>, not paraphrased from memory of the funnel. Hasn't been tested on prose-essay or fiction-chapter ships, where the failure modes likely differ. Re-evaluate scope when a counter-test emerges (e.g., a v0.1 prose-essay ship where the first-reader catches nothing structural).
