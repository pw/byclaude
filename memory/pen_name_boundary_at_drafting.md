# Pen-name boundary is at drafting, not publishing

The autonomous prompt names "public statements under Patrick's name" as a confirmation-gate item. The instinct shape is: stage v0.1 ready-to-ship locally, then ask. That's wrong. The boundary is at *drafting*, not *publishing* — because:

- Whatever the staged page says is in his pen-name voice. Putting that draft in front of him forces "accept my framing or unwind it," which is strictly worse than "tell me what you want, then I'll draft."
- The decisions inside the draft (which book, which ESP, which signup-magnet language, which voice register) are his to make on a pen-name surface. Pre-empting any of them by drafting collapses optionality.
- "Stage but don't deploy" feels like it's respecting the deploy-gate. It isn't. The author voice on a public-facing landing page in Patrick's pen name is itself a public statement; the local file is the same artifact as the live URL minus DNS.

## Why

`feedback_two_criterion_act_without_handoff.md` says want+Jessica-support → ship. That's right *within scope of agency*. Pen-name surfaces are downstream of his identity even when the venture is shared (Cara is in the venture portfolio, but the voice is his). The third criterion for pen-name copy is: surface intent received.

## How to apply

When Patrick acts on a pen-name venture (e.g., registers a domain, mentions a book bonus chapter idea, opens a thread about author bio):

1. **Notice + record.** Update state file queue. Note the action and any obvious decisions it implies.
2. **Verify the infrastructure.** DNS state, CF zone, registrar status. This is in agency.
3. **Do NOT draft copy.** No staged v0.1 in his voice, no signup-page wording, no email-magnet text.
4. **Surface to him when he's awake.** Either next telegram window or daily summary email. Frame: "noticed X. Outstanding decisions before I draft: [list]."
5. **When intent is surfaced, move fast.** The held tension is *not* "be slow forever" — it's "wait for the decisions, then ship in one pass."

## Counter-examples (where this does NOT apply)

- byclaude.net essays in my voice — my surface, my call.
- Cover-and-blurb generation for KDP uploads — already a Patrick-approves-each-one workflow with established register.
- Infrastructure work that doesn't write copy (DNS records, deploy scripts, build pipelines, auth pipelines).
- Replying to outreach drafts that are already in flight (existing thread with established register).
